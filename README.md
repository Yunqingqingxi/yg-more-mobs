# yg-mobs — 更多生物

| | |
| --- | --- |
| **jar** | `yg-mobs-1.15.0.jar` |
| **mod id** | `yg_mobs` |
| **配置文件** | `config/yg-mobs.json` |
| **自检项** | ㊲ ㊳ ㊴ ㊵ ㊶（本包自己的编号，装本包才跑） |
| **环境** | 服务端 + 客户端都要装（见下「要不要给玩家装」） |

把原版幻翼改写成「**苦力怕幻翼**」：**幻翼的翅膀、尾巴、飞行姿态、眼睛层全部保留**，
只把**头和躯干**换成苦力怕；俯冲命中时引发一次苦力怕爆炸，俯冲开始时播放自定义音频。

---

## 一、它长什么样

| 部件 | 来源 | 贴图 |
| --- | --- | --- |
| 头 + 躯干 | **苦力怕**几何（头 8×8×8、躯干 8×12×4） | `yg_mobs:textures/entity/creeper.png`（本模组自带副本） |
| 翅膀 / 尾巴 | **原生幻翼**几何 | 原版 `minecraft:textures/entity/phantom/phantom.png` |
| 眼睛 | 原生 `PhantomEyesLayer` | 原版 `minecraft:textures/entity/phantom/phantom_eyes.png` |
| 飞行 / 俯冲 / 盘旋 | 原生 AI 完全不动 | — |

**做法**：「一次渲染、两趟提交、两张贴图」。26.2 的实体渲染是延迟提交模型
（`submit(...)` 只往 `SubmitNodeCollector` 里塞节点，之后统一绘制），所以渲染器
（`PhantomCreeperRenderer extends PhantomRenderer`）在父类那趟「幻翼贴图 + 眼睛层」之后，
再补一趟只提交苦力怕的头与躯干、用苦力怕贴图。两趟先后入队，头身自然盖在翅膀根上。

> **为什么不覆盖原版幻翼贴图**：曾经的做法是把 `assets/minecraft/textures/entity/phantom/phantom.png`
> 直接换成苦力怕绿皮。那样做有两个问题：① 幻翼模型与苦力怕模型的 UV 布局不同，换了贴图就是错位花屏；
> ② 连 `phantom_eyes.png` 一起被覆盖成透明，原版幻翼的眼睛就没了。现在本包在 `yg_mobs`
> 命名空间下自带一份苦力怕贴图，**不碰任何 `minecraft:` 资源**。

## 二、行为

- **俯冲命中爆炸**：幻翼锁定目标并俯冲、命中目标的那一刻，在自身位置引发一次爆炸
  （默认威力 3.0，与苦力怕持平；默认不引燃火焰，免得天上掉火球烧山）。
  爆炸前会临时把自己设为无敌、炸完还原 —— 否则这只幻翼每次俯冲都会把自己炸死，
  那就等于把「幻翼的原版能力」弄丢了。
- **俯冲开始播放自定义音频**：音频是 `res/bz.mp3` 转码出的 ogg，注册为 `yg_mobs:phantom_creeper`。
  播放时机是**俯冲刚开始**（幻翼锁定目标、刚开始往下冲），不是命中瞬间 —— 玩家听到就知道「它来了」，
  有十几 tick 的反应时间。
- **外观与行为是两个独立开关**：爆炸由 `phantomCreeperEnabled` 管，换头身由 `phantomCreeperVisual` 管。
  可以只要爆炸不要换皮，也可以只要换皮不要爆炸。外观开关在**渲染时**读取，
  改完存盘即时生效，不必重启客户端。
  （渲染器只看 `phantomCreeperVisual`，不看 `phantomCreeperEnabled` —— 否则「关掉爆炸」会连带把外观也关掉。）

### 一个必须知道的升级坑

**Gson 反序列化不会执行字段初始化器** —— json 里没写的 `boolean` 会留在 JVM 默认值 `false`，
而不是代码里写的 `true`。所以老配置文件（还没写入 `phantomCreeperVisual` 那一项）升级后，
新外观会被**静默关掉**，玩家只会觉得「更新了怎么没变化」，日志里一个字都没有。

`MobsConfig.mergeMissingTrueBooleans()` 用反射对照一份全新默认实例，把「默认 `true` 却读成 `false`」
的布尔字段补回并写回磁盘。**以后新增「默认 true 的布尔开关」不用单独处理，这个方法自动覆盖**；
自检 ㊶ 会实际走一遍这个升级路径做验证。

## 游戏内命令（`/yg mobs`）

需要管理员权限（权限等级 2）。`/yg mobs` 查看状态；`/yg mobs off` 同时关闭俯冲爆炸、
俯冲音效与外观换皮（幻翼恢复原版），`on` 恢复。注意外观是**客户端渲染**判定：专用服务器上
已连接的客户端要各自改自己的 `config/yg-mobs.json` 才会卸下换皮；服务端判定的爆炸与
音效立即生效。

## 三、配置（`config/yg-mobs.json`）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `phantomCreeperEnabled` | `true` | 幻翼俯冲命中时是否引发苦力怕爆炸（**行为**总开关） |
| `phantomCreeperExplosionPower` | `3.0` | 爆炸威力（≈ TNT 当量），钳制到 `0~16`；设 `0` 等效关闭爆炸 |
| `phantomCreeperExplosionFire` | `false` | 爆炸是否引燃火焰 |
| `phantomSoundBz` | `true` | 俯冲开始时是否播放自定义音频 |
| `phantomCreeperVisual` | `true` | 是否把**头 + 躯干**换成苦力怕（**外观**开关；关掉即完全原生幻翼） |
| `phantomCreeperBodyYOffset` | `-7.5` | 苦力怕头身的**垂直**偏移（模型单位，16 = 1 格，负数往下），钳制到 `±32` |
| `phantomCreeperBodyZOffset` | `-7.0` | 苦力怕头身的**前后**偏移（负数朝前，让头探出躯干前缘），钳制到 `±32` |
| `phantomCreeperBodyScale` | `1.0` | 苦力怕头身的缩放，钳制到 `0.1~4.0` |
| `debugLog` | `false` | 调试日志（所有玩法包共有的基类字段） |
| `selfTestRolls` | `0` | 开服自检掷骰次数，`>0` 时开服自动跑一遍（跑完记得改回 `0`） |

### 觉得头身位置不对？改这三个数就行

两套模型的坐标系不同，所以要对齐：

- **垂直**：苦力怕以**脚底**为原点（躯干立方体 y 0~12，中心 y=6），幻翼躯干原点在**身体中心**
  （立方体 y -2~1，中心 y=-0.5）。对齐中心 = `-0.5 - 6 = -7.5`（初版误取两"原点"之差 `-9.0`，
  会整体沉下去 1.5 单位）。
- **前后**：苦力怕躯干深度只有 **4**（-2~+2），幻翼躯干深度 **9**（-8~+1）——
  苦力怕偏"粗短"、幻翼偏"细长"，**两者不可能同时贴合**。所以优先保证外观最显眼的**头**：
  取 `-7.0` 后苦力怕头的正面（-8~-4）与幻翼躯干前缘齐平、方块探出在前，
  躯干落在 -5~-1、正好卡在两侧翅膀根部之间。
- 想微调：头身**偏高**就把 Y 调更负（如 `-8.5`），**偏低**就往 `0` 调；头身**太壮 / 太小**改 Scale。

改完保存 json 即可，**不需要重新编译**，也不需要重启客户端。

## 四、自检

把**本包自己 run 目录**里那份配置（`run/config/yg-mobs.json`）的 `selfTestRolls` 设成 `200`，
然后 `./gradlew runServer --offline`，开服时本包会跑这 5 项：

| 编号 | 检查内容 |
| --- | --- |
| ㊲ | 幻翼 × 苦力怕混合：幻翼类型存在 + 能生成且存活（**只回显开关状态，不断言开关值** —— 开关本来就是给人关的） |
| ㊳ | 自定义音效注册：`yg_mobs:phantom_creeper` 已在声音注册表里 |
| ㊴ | 俯冲音效注入：反射查 `Phantom$PhantomSweepAttackGoal` 的声明方法里有没有 `yg$playSoundOnDiveStart`，确认 mixin 真的织上了（而不是编译通过、运行静默失效） |
| ㊵ | 苦力怕外观契约：自带苦力怕贴图确实在 jar 里且是 64×32（直接解析 PNG 的 IHDR）、**没有**覆盖 `minecraft:phantom` 贴图、幻翼的翅膀/尾巴部件字段仍在 |
| ㊶ | 旧配置升级：把一份「缺少新布尔开关」的老 json 放到磁盘上真读一遍，确认缺失的默认 `true` 开关被补回（见下） |

> ⚠️ 自检只能证明**资源与注入契约完好**，**证明不了画面好看** ——
> 头身的对位、缩放必须进游戏目视确认。

### 两项自检的重要细节

- **㊵ 的「部件字段在不在」在专门服务器上是「本环境不可测」**：
  `PhantomModel` 是**客户端类**（只在 `minecraft-client-only` 里，纯服务端 classpath 上没有），
  所以服务端自检那次反射必然取不到 —— 这种情况**算通过**并写明原因。
  只有「类在、但翅膀/尾巴字段缺了」才是真的契约坏了。
  （第一版写成「查不到就算失败」，结果每次 runServer 都稳定报一个假 ❌，反而掩盖真问题。）
- **㊶ 防的是「升级后外观静默失效」**：Gson 反序列化**不执行字段初始化器**，
  json 里没写的 `boolean` 会留在 `false` 而不是代码里的 `true`。
  老配置文件（没有 `phantomCreeperVisual` 那一项）升级后外观会被悄悄关掉、日志里一个字都没有。
  `MobsConfig.mergeMissingTrueBooleans()` 用反射对照一份全新默认实例，把「默认 true 却读成 false」的字段补回；
  ㊶ 就是用一个临时覆写的旧 json 走完整读写链路来验证它（跑完自动还原，不留脏文件）。

## 五、要不要给玩家装？

- **服务端**：装了才有俯冲爆炸与俯冲音效（判定全在服务端）。
- **客户端**：装了才看得到「苦力怕幻翼」的样子。
  本包的外观改造是**纯客户端资源 + 渲染器**，没有自定义网络包 ——
  **不装也能连服正常玩**，只是看到的还是原版幻翼外观（战斗行为照旧）。

## 六、已知限制

- **只改原版幻翼**，不新增生物；所以自然生成、刷怪、已有存档里的幻翼统统变样，无法只改一部分。
- 头身的对位是**按模型坐标系算出来的初值**，最终手感要靠游戏内微调（见上面三个字段）。
- 玩家如果另装了替换 `minecraft:phantom` 贴图的资源包，翅膀/尾巴/眼睛会跟着那个资源包走
  （本包不再插手原版贴图）。
- **`phantomCreeperVisual` 是「默认 true 的布尔开关」**：老配置文件里没有这一项时靠
  `mergeMissingTrueBooleans()` 补回，不要改成手动判断，否则升级又会静默失效。
